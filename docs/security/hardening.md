# Hardening

Status: draft v0.1, 2026-11-02. Part of the [oewang docs](../README.md). Implements [PRD](../prd.md) SEC-9 to SEC-20 and OPS-3.

The controls that are not authentication ([auth](auth.md)) and not payload encryption ([encryption](../api/encryption.md)). Input handling, uploads, outbound calls, browser headers, dependencies, secrets, and what the logs may hold.

## Update this doc when

- Adding a control, or changing a limit in the [limits table](#limits).
- Adding a dependency with a wide blast radius, or changing the dependency policy.
- Changing the Content Security Policy.

## Input validation

Three layers, each with a different job. None of them is optional because another exists.

| Layer | Job | Tool |
|---|---|---|
| Web app | Shape and usability. Tells the user what is wrong before a round trip | Zod schema, shared between the form and its action |
| API handler | Type, range, format, enum. Rejects anything that cannot be a valid request | `serde` plus `validator` on the request struct |
| API service | Business rules that need the database: does this wallet exist in this workspace, is this the last owner | Service code plus database constraints |

Rules:

- A handler never passes an unvalidated struct to a service. Parsing is the validation: the service receives a type that cannot hold an invalid value.
- A service never trusts an ID because the handler saw it. Every ID is re-read with a workspace filter.
- Rejections carry a field map (`VALIDATION_FAILED`, [conventions](../api/conventions.md#the-envelope)). They never echo the submitted value back, so a reflected payload cannot travel through an error message.

### Injection

- **SQL.** Every query goes through `sqlx` with bound parameters. There is no string concatenation into SQL anywhere, including the search filter, which binds a `LIKE` pattern as a parameter. `cargo sqlx prepare` checks every query against the real schema at build time, so a typo is a compile error, not a runtime one.
- **Dynamic sort.** `sort` and `order` are enums mapped to fixed SQL fragments, never interpolated from the request.
- **HTML.** Svelte escapes interpolated text by default. `{@html …}` is used in exactly one place, the rendered Markdown of an assistant message, and that passes through a sanitizer with an allow-list of tags and attributes before it reaches the DOM. No other use of `{@html …}` is permitted; a lint rule enforces it.
- **Path traversal.** A storage key is generated by the API, never taken from a filename. The original filename is stored as metadata and is never used to build a path.

## File uploads

Receipts, statements and the files dropped on the vault page are the only uploads, and they share one path. They are also the most common way in for a malicious file.

| Control | Rule |
|---|---|
| Size | 10 MB maximum, enforced by a body limit layer before the handler reads anything (VLT-1) |
| Declared type | Must be `image/jpeg`, `image/png`, `image/webp` or `application/pdf` |
| Actual type | Sniffed from the leading bytes at completion, not on the first chunk: a client could otherwise send a valid header and anything it liked after it. A mismatch is rejected with `UNSUPPORTED_FILE_TYPE`, and the file and its chunks go with it |
| Filename | Stored as data, never used as a path. The storage key is `wsp/{workspace_id}/{file_id}` |
| Image handling | The API decodes an image in exactly one place: the vault thumbnail (D91). Decoding untrusted images in-process is a known class of memory bug, so it is bounded: the `image` crate with only its JPEG, PNG and WebP decoders, at most 8000px a side and 128 MB of allocation, inside `spawn_blocking`, once per file. A file that fails is marked and never decoded again. The output is a 320x320 JPEG the API wrote itself. This row said "never" until the vault grid needed previews |
| Serving | Bytes are served back through the API in encrypted chunks, with `Content-Type` fixed to the sniffed type and `Content-Disposition: attachment` ([encryption](../api/encryption.md#file-bytes)) |
| SVG and HTML | Not accepted, at all. Both execute script when opened |
| Scope | A file is workspace-scoped. A cross-workspace request returns 404 (VLT-4) |

The AI service receives image bytes to parse. It never writes them anywhere, never logs them, and holds them only for the duration of the call.

## Outbound calls

The API calls five hosts, each from configuration and never from user input: the AI service, object storage, the email provider (`RESEND_API_KEY`, D40), the exchange-rate source (`FX_API_URL`, D44, D96; once a day, from the refresh job only), and the Telegram Bot API (`TELEGRAM_API_URL`, D84). This line said two until Telegram arrived; email and rates had been added without it.

- Telegram is called for `getUpdates`, `sendMessage`, `editMessageText`, `answerCallbackQuery`, `sendChatAction` and `getFile`, and files are downloaded from the same host. The download path comes from Telegram's `getFile` answer and is fetched only when it is a plain relative path; it is never followed as a URL. The download is capped at `MAX_FILE_BYTES` as it streams, whatever size Telegram claimed.
- The bot token is part of every Telegram URL path, so the URL is a secret: the client's `Debug` omits it and every `reqwest` error is stripped of its URL before it is logged.

- There is no endpoint that fetches a user-supplied URL. That removes server-side request forgery as a class, and it stays removed: adding one needs a decision record and an allow-list.
- The AI service calls exactly one host, the API, from `API_INTERNAL_URL`.
- The model has no browsing tool ([PRD non-goals](../prd.md#non-goals-for-v1)), so it cannot be steered into fetching a URL either.

## Browser headers

Set by the SvelteKit server on every HTML response.

| Header | Value |
|---|---|
| `Content-Security-Policy` | `default-src 'self'; script-src 'self'; style-src 'self'; style-src-attr 'unsafe-inline'; img-src 'self' data: blob:; frame-src blob:; connect-src 'self'; font-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'; form-action 'self'` |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` in production |
| `X-Content-Type-Options` | `nosniff` |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |
| `Permissions-Policy` | `camera=(self), microphone=(), geolocation=(), payment=()` |
| `Cross-Origin-Opener-Policy` | `same-origin` |

One implementation, in `apps/app/src/lib/security-headers.ts`: `vite.config.ts` hands the directives to SvelteKit, because only SvelteKit can nonce its own inlined bootstrap script and its own `<style>` element, and `hooks.server.ts` sets the rest. `security-headers.test.ts` snapshots every value, so widening a directive is a failing test and a line in a diff rather than something noticed in production (SEC-15).

Notes:

- No `'unsafe-inline'` in `script-src`. SvelteKit's inlined hydration data is covered by a per-response nonce, which it supports natively.
- **The theme bootstrap lives in `app.html`, carrying `%sveltekit.nonce%`.** `mode-watcher` injects its own copy of that script through `{@html}` with no nonce and an unquoted attribute, so under this policy the browser refuses it and the white flash it exists to prevent comes back. The component is rendered with `disableHeadScriptInjection`, which is the option the library documents for this. Changing either storage key or the dark class name on the component means changing the copy in `app.html`.
- `style-src-attr 'unsafe-inline'` is a deliberate divergence from "no inline anything". Without it, `style-src 'self'` covers attributes too, and the few `style` attributes that carry a per-element geometry value, the upload progress bar's transform and the transactions table's measured total width, stop applying: the table then renders at the wrong width until hydration. It is narrower than it looks, because an injected `<style>` block and a remote stylesheet are both still refused, and writing a style attribute takes HTML injection, which the assistant's renderer forecloses by escaping rather than parsing (SEC-11). Moving those values to CSSOM would close it and cost a first paint.
- `img-src` allows `blob:` because file bytes arrive decrypted in memory and are shown through a Blob URL that is revoked after load ([encryption](../api/encryption.md#file-bytes)).
- `frame-src` allows `blob:` and nothing else, for the one frame the app draws: a PDF in the vault file sheet, shown from the same kind of revoked Blob URL (D91). No remote page can be framed, and the only blob URL is one the page minted from bytes the API sniffed as a PDF (SEC-12). Without the directive `default-src 'self'` refuses a blob frame and the PDF preview is blank.
- `camera=(self)` only because receipt capture on a phone uses it. If capture ships as a file picker instead, drop it to `()`.
- `frame-ancestors 'none'` plus `X-Frame-Options` is redundant; the CSP directive is the one that counts.
- In development SvelteKit adds `'unsafe-inline'` to `style-src` itself, because Vite injects stylesheets at runtime. That is a development-only branch in SvelteKit; a production build serves the table above exactly, which was verified against one rather than reasoned about.

### Liveness

`apps/app` answers `GET /health` with `{"status":"ok"}` and no session, for the container health check. Liveness only: the web app's one dependency is the API, which answers for itself, and a readiness check that reports somebody else's outage gets a working process restarted.

## CORS

The API answers no cross-origin browser request. The only browser-facing origin is the web app, and the browser never calls the API directly (D5). CORS is therefore configured to allow nothing, not to allow the app's origin. If a future client needs direct access, that is a decision record, not a configuration tweak.

## Secrets

| Rule | Detail |
|---|---|
| Source | Environment variables, injected by the deployment. No secret in the repository, no `.env` committed |
| Validation | Every required secret is read and validated at startup. A missing or short `JWT_SECRET` stops the process |
| Comparison | `AI_SERVICE_API_KEY` is compared in constant time |
| Signing key | A PKCS#8 PEM file, mode `0600`, mounted from the secret store ([encryption](../api/encryption.md#server-signing-keys)) |
| Rotation | `JWT_SECRET` rotation invalidates every session, which is acceptable. Signing key rotation is dual-published for 90 days |
| In memory | Keys live in process memory only. Nothing writes a key to disk at runtime |
| Scanning | CI runs a secret scanner over the diff. A hit fails the build |

## Logging

Never logged, in any process (OPS-3):

- Passwords, including inside a request body dump.
- JWTs, whole or partial.
- `JWT_SECRET`, `AI_SERVICE_API_KEY`, the Ed25519 private key, storage credentials, the Anthropic key.
- Decrypted request or response bodies.
- File bytes, receipt images, extracted receipt text, chat message content.
- Anything Telegram sends: message text, captions, files, and the bot's replies. `TELEGRAM_BOT_TOKEN`, and any URL that contains it.

Logged on every request: `request_id`, method, path, status, duration, `user_id`, `workspace_id`. On every chat turn: workspace, session, round count, tool names, token counts, duration.

Enforcement: request and response bodies are never passed to the logger, and secrets live in a newtype whose `Debug` and `Display` implementations print `[redacted]`. A test runs a representative workload against a captured log sink and asserts that no known secret value appears in the output.

## Dependencies

| Rule | Detail |
|---|---|
| Audit | `cargo audit` (Rust), `bun audit` (Node), `pip-audit` (Python), in CI on every pull request into `main` |
| Lockfiles | Committed for all three apps. CI installs from the lockfile, never resolves fresh |
| Crypto | Only the primitives in [encryption](../api/encryption.md#primitives). No hand-rolled crypto, and no crypto dependency outside that list |
| New dependency | Needs a reason in the pull request: what it does, what it would take to not have it |
| Frontend | A dependency that runs in the browser is weighed harder than one that runs on the server. It executes in the same context as the session |
| Supply chain | No post-install scripts in the web app's dependency tree. `bun install --ignore-scripts` in CI |
| Threshold | The build fails on an advisory rated high or above. Anything lower is recorded below rather than ignored silently: a gate nobody can pass is a gate somebody removes |

**Accepted advisories.** Each one is listed with why it does not reach this product. A new one goes here with the same reasoning or it is fixed.

| Advisory | Where | Why it is accepted |
|---|---|---|
| RUSTSEC-2023-0071 | `rsa` 0.9.10, reached through `sqlx-mysql` | No fixed version exists. `sqlx-macros-core` lists `sqlx-mysql` unconditionally, but this build uses PostgreSQL only and `cargo tree -i rsa` finds no path that compiles it. Passed to `cargo audit --ignore` with this reasoning in the workflow, not hidden in a config file |
| GHSA-gcqx-w48m-w2h4 | `deepmerge`, through `@sveltejs/vite-plugin-svelte` | Low. A build-time dependency: it never runs in the browser and never sees a request |

## Rate limits and resource limits

### Limits

| Scope | Limit | Requirement |
|---|---|---|
| Credential routes | 10 requests per 15 minutes per IP | AUTH-6 |
| Authenticated routes | 300 per minute per IP | OPS-5 |
| Unauthenticated routes | 30 per minute per IP | OPS-5 |
| `POST /v1/handshake` | 30 per minute per IP | [encryption](../api/encryption.md#handshake) |
| Chat stream | 20 turns per minute per workspace | SEC-17 |
| Request body | 1 MB, except file chunk routes | SEC-18 |
| File chunk body | 1 MB | [encryption](../api/encryption.md#file-bytes) |
| File size | 10 MB | VLT-1 |
| Upload per workspace per day | 200 files | SEC-18 |
| List `limit` parameter | 100 | [conventions](../api/conventions.md#pagination) |
| Bulk operation size | 500 rows | SEC-18 |
| Import rows per job | 5,000 | SEC-18 |
| Model calls per extracted document | 2 full passes plus 4 targeted field calls | AI-10 |
| Wall clock per extracted document | 45 seconds | AI-10 |
| Request timeout | 30 seconds, except the chat stream | SEC-19 |
| Chat stream timeout | 120 seconds | SEC-19 |
| Database statement timeout | 10 seconds | SEC-19 |
| Database pool | 20 connections, 5 second acquire timeout | SEC-19 |

Every limit above is a configuration value with the listed default, not a literal buried in code, **except two**: the list `limit` parameter and the bulk-operation size. Those are part of the API contract rather than a deployment question. A client pages against them and a change to either is an API change with a client to update, not a knob an operator turns, so they are constants and a test fails if they move. `Config::default_rate_limits` is where the defaults live and a test asserts each one still equals the number in this table, so the two cannot drift apart quietly.

**Credential routes** means the ones something can be guessed at: `register`, `login`, `refresh`, `forgot-password`, `reset-password` and `accept-invite`. An earlier draft of this table said `/v1/auth/*`, which was wrong: `/v1/auth/me` is read on every page load, and ten of those per fifteen minutes would lock a working session out of the product. The limit exists for guessing, so it covers what can be guessed.

Two things are exempt from the per-address budgets. The health routes, which a container probes every few seconds. And `/v1/internal/*`, which one service calls from one address and which is gated by a key rather than by a budget (OPS-6); counting a long chat turn's tool calls against a per-address budget would make the product's own traffic look like an attack. The AI service runs its own limiter on what it will accept.

The window slides rather than resetting on the minute. A fixed window lets a caller spend the whole budget at 11:59:59 and the whole budget again at 12:00:00, which is twice the limit at the one moment anybody would aim for.

The counters live in process memory, so a restart forgives everyone and a second instance counts separately. Both are acceptable: this bounds abuse and spend, it is not accounting, and the alternative is a shared store on the request path of every call (D10). The daily upload ceiling is the exception and is counted from the rows, because a day is long enough that a restart must not hand anybody a fresh allowance.

Behind a reverse proxy every request arrives from the proxy, so `X-Forwarded-For` is read only when `TRUST_PROXY_HEADERS` says there is one in front. Anyone can send that header, and a limiter that believes it is a limiter anyone can step around.

### Why each matters

A body limit layer stops a large body before a handler allocates for it. A statement timeout stops one slow query from holding a pool connection forever. A pool acquire timeout turns pool exhaustion into a fast 503 instead of a hang. The chat turn limit bounds model spend per workspace, which is the only unbounded cost in the system.

## Database

- The application connects as a role that owns no DDL rights in production. Migrations run as a separate role, in a separate step.
- Every workspace-scoped query filters on `workspace_id` ([auth](auth.md#workspace-scoping)). Row-level security is not used; the filter is in the repository and reviewed there. If the number of writers ever grows beyond one process, RLS becomes the right answer and gets a decision record.
- Soft delete everywhere (OPS-2). Nothing in the application issues a `DELETE` against a workspace-scoped table.
- Balance changes lock wallet rows in a stable order (D13, [data model](../data-model.md#balance-arithmetic)).

## Error handling

- An unhandled error returns `INTERNAL_ERROR` with the request ID and nothing else. No message, no backtrace, no SQL text.
- A panic in a handler is caught by a catch-panic layer, logged with the request ID, and returned as `INTERNAL_ERROR`.
- 404 is returned for a row in another workspace, never 403, so existence is not confirmed ([conventions](../api/conventions.md#methods-and-status-codes)).
- Error codes are stable and enumerated. A client branches on the code, never on the message.

## Testing the controls

| Control | Test |
|---|---|
| Workspace isolation | A user of workspace A requests every resource ID of workspace B and gets 404 on each |
| Role gates | Each write route and each write tool is called as `member` and must return 403 |
| Secrets in logs | A representative workload runs against a captured log sink; known secret values must not appear |
| Upload type sniffing | A PHP file renamed to `.jpg`, an SVG, and an oversized file are each rejected |
| Rate limits | The auth bucket is exhausted and the next request returns 429 with `Retry-After` |
| Replay | A captured OWE1 request is replayed and returns `CRYPTO_REPLAY_DETECTED` |
| Tamper | A flipped bit in a ciphertext returns `CRYPTO_DECRYPT_FAILED` |
| CSP | A response header snapshot test, so a loosened policy shows up in review |
| CORS | The `cors` feature of `tower-http` is not enabled, and a test fails if it is ever switched on. A layer whose code is not compiled cannot be added by accident (SEC-16) |
| Prompt injection | The corpus in [AI safety](ai-safety.md#testing) runs against the tool loop |
